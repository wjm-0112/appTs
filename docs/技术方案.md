## 1. 技术决策汇总

| 项 | 结论 | 理由 |
|---|---|---|
| 技术栈 | React 18 + Vite 5 + TypeScript | 纯前端、可离线；TS 保障数据模型演进 |

## 4. 数据模型（TypeScript）

```ts
// —— 静态知识（代码内 readonly 常量，不进 DB）——

  requiredMarkets?: string[]; optional?: boolean }

  name: string; hint: string; targetTab: string }
interface MarketDef { id: string; name: string;
  compare: { topic: string; level: 0|1|2; detail: string }[];  // 0不要求 1建议 2必须

interface MarketTrack { marketId: string;
  account: 'none'|'reviewing'|'certified';
  submit: 'none'|'submitted'|'reviewing'|'passed'|'rejected';
  testAccount?: string; rejectReason?: string;
  lastSubmitAt?: string; launchAt?: string; versionLog: string[] }
interface NoteLog { id: string; type: string; text: string; at: string }
interface AppRecord { id: string; name: string; packageName: string; industryId: string;
  entity: { name?: string; legalPerson?: string; bank?: string };
```

## 5. 阶段派生与公式

```
qual    = 类别∈{主体,知产,备案} 且 !optional 的材料中 终态(obtained|uploaded) 占比
account = markets.filter(account==='certified').length / 6
tech    = min(类别==='包体' 材料完成率, 自查 group==='包体技术' 通过率)
review  = markets.filter(submit==='passed').length / 6
launch  = 任一 markets.launchAt 非空 ? 100% : 0%
当前阶段 = 首个 <100% 的阶段（review 以「已提交任一市场」起算）
自查 %  = 通过数 / (总项数 − 不适用数)；App 完成% = 各组通过合计 / (32 − 不适用合计)
```
进度均为纯函数派生（`deriveStage(app)` / `deriveStats(app)`），不落库。

## 6. 数据库具体方案（IndexedDB）

- 结构：库 `app-submit-db`；objectStore `kv`（keyPath `k`）；`DB_VERSION=1`（仅在 onupgradeneeded 建 store）。数据量小（每 App ≈2–4KB，100 App <500KB），采用**单文档全量原子写**（key `appState`），避免多 store 事务复杂度、保证整库一致。
- 键：`appState` → PersistState；`backup-<ts>` → 快照，保留最近 5 份自动清理；`meta` → 创建版本等。
- **双层版本**：`DB_VERSION`（存储结构）与 `PersistState.version`（数据形态）分离。加载时 `while(v<CURRENT) state = MIGRATIONS[v](state)` 逐级迁移并回写；导入的旧备份走同一迁移链。
- **API（db.ts）**：
  - `openDb()`（单例懒加载）；`loadAppState()`；`saveAppState(s)`（readwrite 原子 put）；
  - `backupSnapshot()`→key / `listBackups()` / `restore(key)` / `deleteBackup(key)`；
  - `resetData()`（仅删 appState）；`exportJson()`；`importJson(text)→{ok,count,backupKey}`；
  - `validateState()` 强校验；`reconcileApp()` 模板升级「只增不改」（补入当前目录新增 defId）。
- **写可靠性**：写队列 promise 链串行 → scheduleSave 防抖 500ms → flush()（unmount / beforeunload / pagehide 尽力执行）→ put 失败重试 1 次，仍失败保留内存副本 + message「保存失败，请导出备份」。
- **多标签同步**：put 成功后 `BroadcastChannel('app-submit-sync')` 广播；接收方本地无未保存改动则直接应用广播状态，否则先 flush 再重读 IDB（last-write-wins）；仅写入方广播防回环；`visibilitychange` 恢复可见时主动重读。
- **降级**：openDb 失败（隐私模式）→ 纯内存运行 + 顶栏警告「当前浏览器无法持久保存」。
- **容量**：设置页以 `navigator.storage.estimate()` 展示用量，接近配额引导导出。

## 7. 状态管理与数据流

```
组件 dispatch(action) → reducer(不可变更新) → Context 状态
  → deriveStats() 重渲染
  → scheduleSave(防抖500ms) → db.saveAppState() → BroadcastChannel 广播
静态知识 constants/* + content/*.md —— 只读，与用户数据完全分离
```
Actions：addApp / updateApp / removeApp / setMaterial / setCheck / setMarket / addNote / removeNote / importAll / reset。加载：`loadAppState` → 迁移 → reconcile 补模板 → 注入 reducer 初始态。

## 8. 主题与知识渲染管线

- 主题：`matchMedia('(prefers-color-scheme: dark)')` 判定；`ConfigProvider theme={{ algorithm: dark? theme.darkAlgorithm: theme.defaultAlgorithm, token:{ colorPrimary:'#2E6BE6', borderRadius:8, fontSize:14 } }}`；监听 change 切换。
- 知识：`const md = import.meta.glob('../content/*.md', {query:'?raw', import:'default'})`；react-markdown + remark-gfm 渲染（表格/任务列表）；样式集中在 kb.css（双主题变量保证暗色对比度）；CopyBlock 复用原文；fenced code 自定义 code 组件支持单块复制；每篇加载带懒加载（React.lazy）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| IDB 异步并发 | 写队列串行 + 防抖 + unmount flush + 失败内存兜底 |
| 迁移损坏 | CURRENT_VERSION + MIGRATIONS 逐级迁移；导入 validateState；保留 backup-<ts> 可回滚 |
| react-markdown 体积 | 仅知识页懒加载（React.lazy 拆包） |
| 暗色对比度 | kb.css 全部用 CSS 变量双主题定义 |
| 政策内容过期 | 每篇/每差异条目带核实时间；升级「只增不改」 |
| 多标签竞态 | BroadcastChannel last-write-wins；仅写入方广播；visibilitychange 补读 |
